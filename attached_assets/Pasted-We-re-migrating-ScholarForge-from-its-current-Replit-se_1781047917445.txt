CHANGE 2 — REPLACE ANTHROPIC WITH GROQ
─────────────────────────────────────────
- Remove all usage of the Anthropic SDK (@anthropic-ai/sdk) across the 
  entire codebase.
- Replace it with the Groq SDK (groq-sdk). Install it as a dependency in 
  the api-server package.
- The default model should be llama-3.3-70b-versatile. Where the original 
  code used claude-haiku-4-5 or claude-sonnet-4-5, switch to this model.
- ALL AI routes must now read the GROQ_API_KEY from the incoming request 
  headers (header name: x-groq-api-key) rather than from server environment 
  variables. Do NOT store the user's key server-side or in any database.
- If the x-groq-api-key header is missing or empty on any AI route, return 
  a 401 JSON response: { "error": "GROQ_API_KEY_REQUIRED", "message": 
  "Please provide your Groq API key to use AI features." }
- On the frontend, add a first-run modal/gate that:
    • Appears on first load (check localStorage key sf_groq_key).
    • Explains that ScholarForge uses Groq's free API for AI features.
    • Provides a direct link to https://console.groq.com/keys so the user 
      can get their key.
    • Has a password-type input field for the key.
    • Has a "Save & Continue" button — stores the key in localStorage as 
      sf_groq_key and dismisses the modal.
    • The app should NOT render any AI-enabled UI until the key is stored.
    • Add a small "Change API Key" button in the settings/nav area so users 
      can update their key at any time.
- Every API call from the frontend that hits an AI route must include the 
  header x-groq-api-key: <value from localStorage sf_groq_key>.
